# OpenCode Governed Remote Operator Decision

Status: APPROVED / GOVERNED
Decision type: Construction-tool/operator policy
Architecture baseline: Architecture Freeze V4/V4.1

## Decision

OpenCode is approved as a replaceable remote/CI execution operator for the HooshyarOS autonomous construction fabric.

This decision does not add an engine, alter Architecture Freeze V4/V4.1, create a new governance hierarchy or make OpenCode a product runtime dependency.

Its purpose is to remove routine human mechanical intervention and increase correct construction throughput through bounded unattended GitHub Actions execution.

## Evidence basis

The repository's bounded OpenCode experiments established:

- successful issue-comment trigger and GitHub Actions execution;
- successful repository inspection and full AGENTS.md reading;
- successful bounded file edit;
- successful exact-content verification;
- successful local commit;
- successful remote push to an isolated branch;
- the remaining PR limitation is a GitHub Actions repository permission restriction, so production promotion will use a deterministic fast-forward gate instead of relying on automatic PR creation.

## Authority boundary

OpenCode is subordinate to:

- Master Charter;
- Governance Charter;
- Architecture Freeze V4/V4.1;
- Assistant Constitution;
- Python/GitHub construction fabric;
- existing engine ownership and test contracts.

OpenCode has no authority over:

- architecture;
- governance;
- product semantics;
- backlog definition;
- engine ownership;
- security boundaries;
- completion rules;
- external production claims;
- persistent construction memory.

## Autonomous permission

Routine construction actions may run without per-stage human approval when the active operator contract authorizes them.

This includes repository audit, one-knot implementation/repair, focused verification, evidence generation, commit, push and safe fast-forward promotion.

Protected or contradictory actions enter BLOCKED; they do not become approval prompts.

## Model policy

Automatic use is free-only.

The tested default is opencode/big-pickle.

No paid model may be selected automatically.

Alternative free models require repository-specific benchmark evidence before automatic promotion into the automatic model policy.

## Privacy boundary

Free-model use must comply with current provider privacy terms. No customer financial data, personal data, secrets or confidential external-company material may be sent to free-model endpoints where current free-period terms permit model-improvement use.

## Reversibility

OpenCode is replaceable. Disabling its workflow or removing the operator contract must not invalidate the product architecture or canonical construction contracts.

## Approved operating loop

READ → AUDIT → RECONCILE → SELECT ONE KNOT → PLAN → IMPLEMENT/REPAIR → VERIFY → EVIDENCE → COMMIT → PUSH → SAFE PROMOTE → REPLAN

## Stop rule

When evidence, architecture, governance or security is insufficient, the operator must stop in BLOCKED and preserve exact failure evidence.

No blind retry and no fabricated completion are permitted.
