# Final Product Factory

This is the executable productization path for HooshyarOS.

`READ → AUDIT → SELECT → IMPLEMENT → TEST → INTEGRATE → RUN → ACCEPT → REPAIR → COMMIT → PUSH → REPLAN`

The factory is the only completion path for commercial productization. Audit-only evidence, unit evidence, or engine existence cannot declare product completion.

## Required acceptance

The factory must prove a representative customer journey on the real runtime:

`Session → Stable Tenant → Financial Ingestion → Analysis → Dashboard → Restart → Recovery`

A failure is preserved as evidence and must enter a bounded repair loop. A successful audit without application acceptance is not completion.

## Human boundary

Human intervention is reserved for external credentials, approvals, production resources, legal/compliance decisions, and unresolved consequential decisions. Mechanical construction, verification, repair, commit and push remain inside the approved Python/GitHub/Assistant construction fabric.

## Release states

- `BLOCKED`: a required stage failed or evidence is insufficient.
- `COMPLETE`: the representative application acceptance path and required repository evidence passed.
- `BLOCKED_EXTERNAL_DEPENDENCY`: safe repository work is complete but an unavailable external resource prevents release.

`COMPLETE` does not waive external production acceptance, Android/web-device acceptance, or payment/cloud activation requirements when those are part of the approved scope.
