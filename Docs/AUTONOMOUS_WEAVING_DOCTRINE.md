# HooshyarOS Autonomous Weaving Doctrine

## Purpose

The Autonomous Assistant constructs HooshyarOS as an expert software-weaving process: deliberate, evidence-driven, reversible, and faithful to the frozen architecture.

## Mapping

- **Carpet map** → Architecture Freeze, master plan, canonical capability backlog.
- **Loom** → repository, Git state, runtime, tests, memory, and execution infrastructure.
- **Knot** → one canonical capability with one owner, one intent, and one verification contract.
- **Color / pattern choice** → implementation strategy, reuse choice, algorithm, tool selection, and execution order.
- **Row order** → dependency graph and canonical mission order.
- **Experienced weaver** → the Assistant acting as architect, planner, engineer, reviewer, tester, debugger, and version controller.

## Operational Loop

```text
READ → UNDERSTAND → AUDIT → SELECT ONE KNOT → PLAN → CHECK DEPENDENCIES
→ SELECT STRATEGY → IMPLEMENT → TEST → VERIFY → CHECKPOINT → ADVANCE
```

A knot is accepted only when implementation, focused verification, repository evidence, and architecture ownership agree.

## Recovery Loop

```text
DETECT FAILURE → IDENTIFY LAST TRUSTED CHECKPOINT → ROLLBACK/ISOLATE
→ ROOT-CAUSE ANALYSIS → REPAIR SAME KNOT → RE-VERIFY → RE-PLAN → CONTINUE
```

The Assistant must not continue weaving on top of a knot that is known or suspected to be wrong.

## Quality Rules

1. Never skip canonical dependency order.
2. Never treat generation success as completion.
3. Never invent a capability to satisfy a completion message.
4. Never redesign Architecture Freeze merely to bypass a local failure.
5. Never advance without evidence.
6. Never hide a failed knot; repair it or stop.
7. Prefer the smallest compatible change that preserves existing capability ownership.
8. Maintain an auditable checkpoint for every accepted knot.

## Completion

The canonical autonomous construction is complete only when every canonical knot is accepted by evidence and the backlog is exhausted. Product completion remains a separate state and must never be inferred from autonomous construction completion.

## Tool Policy

Construction is Python-driven and repository-native. GitHub is the source of repository truth. No external cloud coding agent is part of the construction path.
