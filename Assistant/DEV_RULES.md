# HooshyarOS Development Rules

## Mission

Build with maximum simplicity and maximum quality.

---

# Golden Rules

1. Simplicity beats complexity.

2. Never create code that is not needed today.

3. Every module must be replaceable.

4. Every file must have one responsibility.

5. Every function must be understandable.

6. Documentation is part of development.

7. Every commit must improve the project.

8. Never duplicate logic.

9. Every important decision must be reviewable.

10. If a simpler solution exists, use it.

---

# Coding Order

Think

↓

Design

↓

Review

↓

Implement

↓

Test

↓

Document

↓

Commit

---

# Stop Rules

Stop development if:

- Architecture becomes unclear.
- Ethics become questionable.
- Complexity increases unnecessarily.
- Human understanding decreases.

---

# Success

Good code is not code that works.

Good code is code that improves the future.
