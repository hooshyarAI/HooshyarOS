6. NEW DELTA - additional bounded acceptance-harness robustness defects (K8 scope, not product)
================================================================================
Two additional defects were found in `scripts/installed-product-acceptance.cjs` while
re-accepting the rebuilt artifact. Both are test-infrastructure robustness defects; neither
weakens any acceptance criterion and neither changes product code.

D1 - isolated acceptance installer auto-launch races the harness launch:
  The generated isolated .iss inherited `[Run] ... Flags: runhidden nowait`, so the silent
  acceptance install auto-started a runtime that opened the same <app>\data\hooshyar.sqlite
  while the harness started its own runtime. Observed failure:
    Error: database is locked  (ERR_SQLITE_ERROR, errcode 5)
    at new SQLitePersistenceStore (Backend/HBOS/Product/SQLitePersistenceStore.ts:21)
  -> the runtime exited before becoming healthy.
  Repair: append `skipifsilent` to the generated ISOLATED installer's [Run] line only. The
  production installer (installer/HooshyarOS.iss) is unchanged and still auto-launches for
  interactive users. The harness's real-shortcut launch becomes the single deterministic launch.

D2 - launcher exit event could be missed (TOCTOU):
  `waitLauncherExit()` attached `child.once('exit')` only AFTER `waitHealth()`. When the
  launcher exits immediately after health (measured: 243 ms after health, exit 0), the exit
  event could fire before the listener was attached, so the promise resolved only via its
  bounded 5 s timer and reported a false "shortcut launcher did not exit".
  Repair: capture the child exit promise at spawn time (`launchInstalledShortcut`) and have
  `waitLauncherExit` resolve from it. The bounded window and the requirement for exit code 0
  are unchanged.

Verification after repair: acceptance exit code 0, PASS, 16/16. Independent controlled
launcher measurement (real installed shortcut): health in 3007 ms, launcher exit 243 ms after
health, exit code 0.
