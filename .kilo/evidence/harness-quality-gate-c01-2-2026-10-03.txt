P1  H10-001  CONDITIONAL ASSERTION BYPASS - FALSE GREEN
    Severity : P1 (gate-blocking)
    Location : CognitiveCapabilitySelection.c01-2.test.ts:426-428, 450-452,
               515-517, 586-597
    Statement: Assertions whose reachability is conditional on the very behaviour
               they verify. When the capability does not execute, or the
               governance entry is absent, or no observation matches, zero
               assertions run and the test is reported PASS.
    Concretely: the ORGANIZATIONAL and DECISION tests each contain an "executed
               path" assertion that can only run if the capability already
               EXECUTED. The harness therefore cannot distinguish
               "ORGANIZATIONAL_PROBLEM_SOLVING executed with real evidence" from
               "ORGANIZATIONAL_PROBLEM_SOLVING silently degraded to UNAVAILABLE"
               - the exact failure mode C-01.2 exists to prevent. The
               "reasoning cannot invent a capability result" negative test can
               execute its checks zero times.
    Why P1    : This defeats the knot's central claim. A regression in capability
               execution, or in reasoning-knowledge containment, would be reported
               as 22/22 PASS. Passing evidence produced by a harness that cannot
               fail on the target behaviour must not be promoted as capability
               completion - it is worse than no evidence, because it is
               indistinguishable from valid evidence in the record.
    Remediation: assert the executed status unconditionally
               (`expect(opsCapB!.status).toBe("EXECUTED")`) for the positive
               legs, or invert to assert UNAVAILABLE explicitly with a reason; make
               the execution-order law unconditional by requiring GOVERNANCE to
               be present before comparing indices; and require at least one
               matching observation (`expect(observedMatching.length)
               .toBeGreaterThan(0)`) before iterating knowledge items.
    Retest   : re-run C-01.2 and confirm the guarded legs still pass WITH the
               assertions executing (assertion counts must increase, not the pass
               count alone).

P2  H10-002  NEGATIVE TEST DOES NOT ASSERT ITS NAMED OUTCOME - NO DENIAL ASSERTION
    Severity : P2
    Location : CognitiveCapabilitySelection.c01-2.test.ts:559-570
    Statement: "Unauthorized consequential action -> governance DENIED / no
               execution" asserts only that the GOVERNANCE capability is defined
               and EXECUTED. No DENY verdict, no blocked action, and no
               absence-of-execution is asserted; the body terminates on an
               unfinished comment. The `viewerContext` helper defined at line 70
               is never used anywhere in the harness - the denial scenario is
               registered as an owner-level tenant, so the authorization gap the
               test claims to probe is not actually probed.
    Impact   : governance DENY behaviour is claimed in the harness header (item
               17) and in the C-01.2 evidence narrative, but no executed assertion
               substantiates it. Likewise the cross-tenant test (572-582) checks
               only memory/learning retrieval counts for a GENERAL question and
               never inspects tenant B's evidence for visibility in tenant C's
               capability or evidence fields.
    Remediation: assert the concrete denial (governance verdict DENIED /
               consequence blocked / no action executed) using the declared
               `viewerContext` READ-only principal, and extend the cross-tenant
               test to assert that no evidence reference, capability result, or
               unavailableReason in tenant C names tenant B's artifacts.
    Retest   : negative assertions must fail when governance is stubbed to always
               allow (mutation check), proving the harness detects denial loss.

P2  H10-003  SILENT EARLY RETURN - "NO BENCHMARK" REPORTS AS "ALL GREEN"
    Severity : P2
    Location : CognitiveCapabilitySelection.c01-2.test.ts:55-57 (swallowed
               discovery error), 306, 619 (`if (!REAL) return;`), and the
               `if (REAL)` blocks at 333, 421, 445, 548, 574.
    Statement: When the real benchmark is absent, two tests return early having
               executed nothing and are counted as passed; five further
               assertions are skipped by guard; and the discovery failure is
               swallowed by an empty catch. The suite reports PASS with no
               indication that its strongest evidence did not run. This is the
               mechanism by which H-07's hardcoded path silently converts a
               machine-dependent harness into a false green elsewhere.
    Impact   : the 22/22 figure is not portable evidence. On a host without
               `C:\Users\avalipour\Desktop`, the same command yields 22 passed
               with materially less coverage.
    Remediation: replace early returns with `describe`/`test` gating driven by the
               fixture (`(REAL ? describe : describe.skip)`) so absence is visible
               as SKIPPED, log the resolved fixture path (or the absence) to
               stderr, and remove the empty catch in favour of an explicit
               diagnostic.
    Retest   : run once with `HOOSHYAR_REAL_XLSX` unset/absent and confirm the
               output reports skips rather than passes.
