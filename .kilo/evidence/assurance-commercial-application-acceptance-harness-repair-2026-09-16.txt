(scripts/commercial-application-acceptance.cjs, npm `product:commercial:acceptance`)

4. ROOT CAUSE (proven, not inferred)
================================================================================
scripts/commercial-application-acceptance.cjs launched its nested steps with
  const npm = process.platform === 'win32' ? 'npm.cmd' : 'npm';
  spawnSync(npm, ['run', name], { shell: false, stdio: 'inherit', ... })
Node refuses to spawn a `.cmd`/`.bat` file with `shell: false` and reports EINVAL
before the child process starts, so `result.status` was `null`, the `?? 1`
fallback produced exit code 1, and the ignored `result.error` hid the cause.

Host probe (fresh, this knot):
  shell:false npm.cmd -> status null  error EINVAL
  shell:true  npm     -> status 0     error undefined
  cmd.exe /d /s /c npm -> status 0    error undefined

This matches the pre-existing bounded observation recorded at K3
(.kilo/plans/post-k3-bounded-reaudit-2026-09-14.md §8 and Master Charter §15.1.1),
which had classified it as "a pre-existing aggregate-wrapper launcher quirk only ...
recorded, not silently modified". This knot closes that observation with a bounded repair.

5. REPAIR (one canonical owner, minimum coherent change)
================================================================================
Owner: scripts/commercial-application-acceptance.cjs  (unchanged public contract:
same npm script name, same evidence path, same evidence schema, same exit semantics).

- The npm CLI is now launched through the platform command processor on Windows
  (`process.env.ComSpec || 'cmd.exe'` with `/d /s /c "npm <args>"`), the same
  convention already used by scripts/web-product-acceptance.cjs,
  scripts/security-tenant-acceptance.cjs, scripts/autonomous-factory-loop.cjs and
  scripts/autonomous-ci-repair-loop.cjs. POSIX still spawns `npm` directly.
- The launcher no longer hides the cause: spawn errors are surfaced as
  `launcherError` and an abnormal signal as `signal` in the failure artifact
  (the K8 lesson: never discard the launcher's exit code/stderr).
- `runScript` validates the capability script against the fixed canonical list and
  fails closed with COMMERCIAL_ACCEPTANCE_UNKNOWN_SCRIPT.
- `main()` is guarded by `require.main === module` and the launch helpers are
  exported so the real launch path is behaviorally testable.

No capability was reordered, added or removed; no acceptance criterion was
weakened; no product code was touched.
