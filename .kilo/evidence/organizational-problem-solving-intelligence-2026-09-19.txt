## 2. New capability — canonical owner and real handoffs

Owner: `Backend/HBOS/Product/OrganizationalProblemSolvingService.ts` (Product composition owner, **not** a sixth engine).

Lifecycle stages: `OPEN → DEFINED → EVIDENCE_SET → HYPOTHESES_FORMED → ROOT_CAUSE_IDENTIFIED → OPTIONS_EVALUATED → DECISION_PENDING_APPROVAL → DECIDED → ACTION_PLANNED → EXECUTED → RESOLVED → LEARNED`.

Engine/owner handoffs (all real calls):

| Stage | Canonical owner invoked | What it produces |
|---|---|---|
| HYPOTHESES | `ReasoningEngine.reason` + `OrganizationalIntelligenceEngine.diagnose` | evidence-bound reasoning provenance; structured root causes, affected processes, recommendations |
| ROOT_CAUSE | rank over the engine diagnosis + evidence coverage | primary/ranked causes with support ratios |
| OPTIONS | `ReasoningEngine.reason` (+ optional `DecisionWorkbench` Expert Choice ranking) | scenario reasoning provenance; optional TOPSIS/AHP ranking |
| DECIDE | `GovernanceEngine.evaluate({ action: "APPROVE_DECISION" })` | ALLOWED / DENIED / REVIEW_REQUIRED with policy trace; approvals fail closed |
| PLAN / EXECUTE | `AutonomousOperationsEngine.planWorkflow` / `executeAuthorizedWorkflow` / `monitorExecution` | governed workflow plan, authorized execution, monitor; restart recovery by deterministic re-plan |
| OUTCOME | `ImpactMeasurementService.measure` + `OrganizationalIntelligenceEngine.learnFromExecution` + `ExecutiveIntelligenceEngine.evaluatePerformance` | measured before/after impact, sustainability, ROI, executive achievement rate |
| LEARNING | `KnowledgeEngine.learn` (+ persisted case record) | reusable organizational knowledge bound to the case signature |

Persistence: tenant-scoped records through the canonical `SQLitePersistenceStore` (`problem-case:<id>`, `problem-case-index`); survives restart; cross-tenant reads return null/404.

Metrics (real measurements, no invented scores): `timeToDefinitionMs`, `diagnosisTimeMs`, `diagnosisToDecisionMs`, `decisionToActionMs`, `timeToResolutionMs`, `evidenceCompleteness`, `recurrenceCount`, `actionOutcome`, `outcomeAttainment`, `futureResolutionSpeedMs`.

Security/tenancy: service enforces tenant match and EXECUTE authority on execution; runtime enforces RBAC (`CREATE_DECISION`/`APPROVE_DECISION`/`READ_DASHBOARD`), object authorization (creator or ADMINISTER), and the canonical `TenantIsolation` boundary; decisions route through `GovernanceEngine` and executions are attributed to an explicit `AutonomousOperation` principal.

## 4. Installed-product honesty repair

`Backend/HBOS/Autonomous/Runtime/RuntimeDependencyProbe.ts` (new, non-Engine): resolves `HOOSHYAR_PYTHON` or PATH `python`, reports `{ id, available, source, detail }` and never throws. Wired into `/api/ready` (lazy, cached) and the startup log of `start-commercial-runtime.ts`.

Observed real state: `dist/productization/windows/payload` ships `node-runtime` and `Backend/AI_Runtime`, but **no Python interpreter**; `FinancialStatementAnalysisService.execute` returns BLOCKED when reasoning fails, so the core analysis journey depends on a Python runtime the installer does not ship. The probe makes the dependency explicit at runtime; the underlying product decision (ship Python vs. make reasoning optional) is recorded as an open product/business decision, not silently claimed complete.
