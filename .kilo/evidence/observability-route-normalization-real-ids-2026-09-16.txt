1. DISCOVERY (current-state scan)
--------------------------------------------------------------------
`Backend/HBOS/Autonomous/Runtime/RuntimeObservability.ts` documents its own
contract as "bounded operation counters (requests/errors/duration) per normalized
route" and collapses identifier-like segments via:

  ID_SEGMENT = /^(?:[0-9a-f]{8,}|[0-9a-f]{8}-[0-9a-f-]{4,}|\d+)$/i

Only pure-hex / UUID / decimal segments are collapsed. The three dynamic route
families in `CommercialRuntimeServer.ts` and the real ids they carry are:

  /api/sources/<sha>                     sha256 64 hex          -> collapsed (OK)
  /api/execution/work-items/<id>[/<act>] id = ProvenanceTrace    -> NOT collapsed
  /api/report/artifacts/<id>/download    id = report-<32 hex>   -> NOT collapsed

Canonical producers:
  - work-item id: `Backend/HBOS/Core/ProvenanceTrace.ts:53` createTraceId()
      returns `TRACE-${timestamp36}-${random36}-${counter}` (contains letters
      outside a-f and hyphens).
      Used at `Backend/HBOS/Product/OrganizationalExecutionCoordinator.ts:328`.
  - report artifact id: `Backend/HBOS/Product/ReportExportService.ts:122`
      returns `report-${randomBytes(16).toString("hex")}`.

Consequence: every distinct work item and every distinct report artifact created
its own permanent entry in the server-wide `routes` map. Route cardinality grew
without bound for the process lifetime (an unbounded memory/observability defect
in a long-running commercial runtime) and the metrics surface could never report
per-route aggregates for those two real object families.

The only guard (`Backend/HBOS/test/RuntimeObservability.test.ts`) asserted a
synthetic pure-hex segment (`deadbeefcafe`) that no real endpoint emits, so the
regression passed while the real behaviour was unguarded.
